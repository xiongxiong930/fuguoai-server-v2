# 小程序对接文档 · 自进化能力

> 适用版本：服务端 `⑯ 人格管理 API`（prod-20260730-persona），并涵盖 `⑰ 家庭 RAG`（prod-20260730-rag）的用户可见行为。
> 读者：小程序前端 / 小程序后端对接同学。
> 本文只讲**小程序需要主动对接**的接口与**用户可见**的新行为。纯后端内部能力（离线兜底、A/B、自评估打分）不在对接范围内，仅作行为说明。

---

## 1. 基础约定

| 项 | 值 | 说明 |
|----|----|------|
| Base URL | 与现有小程序调用的其他 `/api/v1` 接口**同一个** | 线上 HTTP 端口为 `8002`（缺省 `8003`），前缀 `/api/v1` |
| 鉴权 | `Authorization: Bearer <小程序用户 JWT>` | 复用现有小程序登录态，**与对讲 / 设备列表接口同套守卫** |
| 设备归属 | 调用者必须已绑定该设备 | 非本人 / 不存在统一返回 `404`（不泄露设备是否存在） |
| 设备 ID（device_id） | **传原始 MAC 即可**，如 `94:a9:90:1a:88:18` | 服务端内部会 `normalize_device_id` 归一化，与设备端对话使用的 ID 形态一致，**无需小程序自己归一化**；路径里建议对 `:` 做 URL 编码（`%3A`） |
| 响应格式 | 成功 `{"ok": true, "data": {...}}`；失败 `{"code": <HTTP状态>, "message": "..."}` | 与现有设备接口一致 |
| CORS | 已放开 `*` | 若小程序走 webview 内 H5 调试可直接跨域调用 |

## 2. 人格管理 API（核心对接点）

让小程序**按设备设置 AI 说话人格**：自称、语气、性格、口头禅、禁忌。设置后该设备**下一轮对话立即生效，无需重启**。

### 2.1 字段说明

| 字段 | 类型 | 含义 | 约束 |
|------|------|------|------|
| `name` | string | AI 自称，如「小福」 | ≤16 字 |
| `style` | string | 语气风格，如「温暖、简洁、自然口语」 | ≤64 字 |
| `traits` | list | 性格特点，如 `["幽默","有耐心"]` | 逗号串或数组 |
| `catchphrase` | string | 口头禅，如「没问题包在我身上」 | ≤32 字 |
| `taboo` | list | 禁忌话题（绝不主动提及），如 `["政治","疾病"]` | 逗号串或数组 |

> 所有字段可选。未设置时设备使用服务端默认人格（config 层可配，默认自称「复果」）。

### 2.2 GET 读取当前生效人格

```
GET /api/v1/persona/{device_id}
```

响应 `data`：

```json
{
  "device_id": "94a9901a8818",
  "enabled": true,
  "persona": {
    "name": "小福",
    "style": "温暖、简洁、自然口语",
    "traits": ["幽默", "有耐心"],
    "catchphrase": "没问题包在我身上",
    "taboo": ["政治"]
  },
  "custom": {
    "name": "小福",
    "traits": ["幽默", "有耐心"]
  }
}
```

- `persona`：三层合并后的**最终生效值**（默认层 + 配置层 + 文件层）
- `custom`：仅文件层（本 API 写入的部分），用于回显「哪些是你改过的」

### 2.3 PUT 部分更新人格

```
PUT /api/v1/persona/{device_id}
Content-Type: application/json
```

**只传要改的字段即可**，未传字段保持不变。

请求体示例：

```json
{
  "name": "小福",
  "style": "活泼,简洁",
  "traits": "幽默,有耐心",
  "taboo": ["政治", "疾病"]
}
```

- `traits` / `taboo` 接受**数组**或**逗号分隔字符串**（服务端自动拆数组）
- 想把某字段**清回默认**：显式传 `null`，如 `{"catchphrase": null}`
- 未知字段会被**静默忽略**，不会报错也不会写入
- 类型错误（如 `name` 传数字）返回 `400` 并带中文错误信息

响应同 GET（返回更新后的 `persona` 与 `custom`）。

### 2.4 DELETE 清除自定义人格

```
DELETE /api/v1/persona/{device_id}
```

清除该设备的文件层，回到默认 / 配置层（等同于把所有字段清回默认）。响应 `custom` 为空对象。

### 2.5 GET schema（前端渲染表单用）

```
GET /api/v1/persona/{device_id}/schema
```

返回字段元数据，**无需设备归属**，登录即可调：

```json
{
  "ok": true,
  "data": {
    "fields": {
      "name": {"label": "自称", "type": "string", "hint": "AI 用来称呼自己的名字，如「小福」", "max_len": 16},
      "style": {"label": "语气风格", "type": "string", "hint": "如「温暖、简洁、自然口语」", "max_len": 64},
      "traits": {"label": "性格特点", "type": "list", "hint": "多个用逗号分隔，如「幽默,有耐心」"},
      "catchphrase": {"label": "口头禅", "type": "string", "hint": "偶尔会蹦出的口头禅", "max_len": 32},
      "taboo": {"label": "禁忌话题", "type": "list", "hint": "绝不主动提及的话题，多个用逗号分隔"}
    },
    "merge_layers": ["config.persona.default", "config.persona.devices", "data/.persona.yaml(本API写入)"]
  }
}
```

小程序可直接据此 schema 动态渲染「人格设置」表单，无需硬编码字段。

### 2.6 错误码

| HTTP | 含义 | 处理建议 |
|------|------|----------|
| 400 | 请求体非 JSON / 非对象 / 无已知字段 / 字段类型错误 | 检查请求体，参考 schema 的 `type`/`max_len` |
| 401 | 未带 / 非法 JWT | 引导重新登录 |
| 404 | 设备不存在或当前用户未绑定该设备 | 不区分「不存在」与「无权限」，前端统一提示「设备不可用」 |
| 500 | 服务端读取 / 写入异常 | 重试；持续 500 联系后端 |
| 503 | persona 模块未初始化（配置未开） | 联系后端确认 `persona.enabled` |

## 3. 调用示例

### 3.1 curl

```bash
# 设置人格（注意 device_id 含冒号建议编码为 %3A）
curl -X PUT 'https://<HOST>:8002/api/v1/persona/94%3Aa9%3A90%3A1a%3A88%3A18' \
  -H 'Authorization: Bearer <小程序JWT>' \
  -H 'Content-Type: application/json' \
  -d '{"name":"小福","style":"活泼,简洁","traits":"幽默,有耐心"}'

# 读取
curl 'https://<HOST>:8002/api/v1/persona/94%3Aa9%3A90%3A1a%3A88%3A18' \
  -H 'Authorization: Bearer <小程序JWT>'
```

### 3.2 小程序 JS（wx.request）

```js
const BASE = 'https://<HOST>:8002';
const enc = (id) => encodeURIComponent(id); // 处理 MAC 里的冒号

// 设置人格：只传要改的字段
function setPersona(deviceId, patch, token) {
  return new Promise((resolve, reject) => {
    wx.request({
      url: `${BASE}/api/v1/persona/${enc(deviceId)}`,
      method: 'PUT',
      header: { Authorization: `Bearer ${token}`, 'Content-Type': 'application/json' },
      data: patch, // 例：{ name: '小福', style: '活泼,简洁', traits: '幽默,有耐心' }
      success: (r) => (r.data.ok ? resolve(r.data.data) : reject(r.data)),
      fail: reject,
    });
  });
}

// 读取当前生效人格（用于进入设置页回显）
function getPersona(deviceId, token) {
  return new Promise((resolve, reject) => {
    wx.request({
      url: `${BASE}/api/v1/persona/${enc(deviceId)}`,
      method: 'GET',
      header: { Authorization: `Bearer ${token}` },
      success: (r) => (r.data.ok ? resolve(r.data.data) : reject(r.data)),
      fail: reject,
    });
  });
}

// 进入设置页：先拉 schema 渲染表单，再拉 getPersona 回显 custom
async function openPersonaSettings(deviceId, token) {
  const [{ data: { fields } }, { persona, custom }] = await Promise.all([
    fetchSchema(token),
    getPersona(deviceId, token),
  ]);
  // fields -> 渲染表单；custom -> 预填已设值；persona -> 展示「当前生效」
}
```

## 4. 生效机制与用户可见行为

- **运行时生效**：PUT / DELETE 写入 `data/.persona.yaml` 后，服务端有 5 秒 mtime 缓存刷新窗口，**最长 5 秒内**、通常**下一轮对话**即生效，无需重启设备或服务。
- **按设备隔离**：每台设备有独立人格；改 A 设备不影响 B 设备。
- **用户感知**：设置后，该设备的复果说话风格 / 自称 / 口头禅立即变化，禁忌话题不会被主动提起。
- 推荐交互：设置页保存成功后，提示「已生效，和 TA 说句话试试～」。

## 5. 家庭知识管理 API（主动录入，维度⑤延伸）

服务端具备**家庭知识记忆**（维度⑤）：对话中用户提到的家庭客观事实会被后台自动抽取存储（自动沉淀）；**同时小程序可主动录入 / 管理**（主动录入），双通道让设备「记住家里的事」并在相关对话语义召回注入。

### 5.1 端点总览

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/v1/family-knowledge/{device_id}` | 列出该设备全部家庭知识（不含向量） |
| POST | `/api/v1/family-knowledge/{device_id}` | 新增 / 更新一条（body: `content` 必填，其余可选） |
| DELETE | `/api/v1/family-knowledge/{device_id}?fact_id=xxx` | 删除单条 |
| DELETE | `/api/v1/family-knowledge/{device_id}/all` | 清空全部（body 须 `{"confirm":"YES"}`） |
| GET | `/api/v1/family-knowledge/{device_id}/schema` | 类别元数据（渲染录入表单用，需登录无需归属） |

> 鉴权 / 设备 ID / 归属 / CORS 与第 2 节人格 API **完全相同**（同一套 `api_guard` + 设备绑定守卫）。`FamilyRAG` 未启用时 GET 返回空列表、写操作返回 `503`。

### 5.2 字段与类别

POST 请求体：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `content` | string | 是 | 事实陈述，≥2 字；相同内容视为同一条（更新不去重新增） |
| `category` | string | 否 | 类别，见下表；非法值自动回退 `other` |
| `tags` | list/string | 否 | 关键词标签，数组或逗号串 |

类别（`category`）取值：

| 值 | 含义 |
|----|------|
| `family` | 家庭成员 |
| `pet` | 宠物 |
| `habit` | 生活习惯 |
| `schedule` | 日程 |
| `preference` | 偏好 |
| `item` | 物品位置 |
| `health` | 健康 |
| `other` | 其他 |

单条返回（含 `id`，删除时用）：

```json
{
  "id": "a1b2c3d4e5f6a7b8",
  "content": "我家猫叫咪咪",
  "category": "pet",
  "tags": ["猫", "咪咪"],
  "ts": 1753800000,
  "weight": 1.0
}
```

### 5.3 调用示例

```bash
# 录入（注意 device_id 含冒号建议编码为 %3A）
curl -X POST 'https://<HOST>:8002/api/v1/family-knowledge/94%3Aa9%3A90%3A1a%3A88%3A18' \
  -H 'Authorization: Bearer <小程序JWT>' \
  -H 'Content-Type: application/json' \
  -d '{"content":"我家猫叫咪咪，橘猫","category":"pet","tags":["猫","咪咪"]}'

# 列表
curl 'https://<HOST>:8002/api/v1/family-knowledge/94%3Aa9%3A90%3A1a%3A88%3A18' \
  -H 'Authorization: Bearer <小程序JWT>'

# 删除单条
curl -X DELETE 'https://<HOST>:8002/api/v1/family-knowledge/94%3Aa9%3A90%3A1a%3A88%3A18?fact_id=a1b2c3d4e5f6a7b8' \
  -H 'Authorization: Bearer <小程序JWT>'

# 清空（需 confirm）
curl -X DELETE 'https://<HOST>:8002/api/v1/family-knowledge/94%3Aa9%3A90%3A1a%3A88%3A18/all' \
  -H 'Authorization: Bearer <小程序JWT>' \
  -H 'Content-Type: application/json' \
  -d '{"confirm":"YES"}'
```

### 5.4 生效与用户可见

- 录入 / 更新 / 删除**实时写入** `data/family_rag/{device_id}.json`，**下一轮对话**相关召回即生效（无需重启）。
- 用户可在小程序「家庭档案」页增删改家庭知识，设备随后对话即「懂家里的事」。
- 自动抽取（对话沉淀）与主动录入共用同一存储，互不冲突；相同 `content` 自动去重。

### 5.5 错误码

| HTTP | 含义 |
|------|------|
| 400 | 请求体非 JSON / `content` 缺或 <2 字 / `category` 非字符串 / `tags` 非数组或逗号串 / 删单条缺 `fact_id` / 清空缺 `confirm` |
| 401 | 未带 / 非法 JWT |
| 404 | 设备不存在或无权访问 / 删除不存在的 `fact_id` |
| 500 | 服务端写入 / 读取异常（含 embedding 异常） |
| 503 | `FamilyRAG` 未启用 |

## 6. 其他自进化能力（无需对接，仅行为说明）

| 能力 | 用户可见变化 | 小程序需做 |
|------|--------------|-----------|
| 离线兜底（维度④） | LLM 全挂时设备不再「死寂」，会回一句兜底话术 | 无需对接 |
| A/B 测试（维度④） | 后端按设备分桶灰度不同采样，用户无感 | 无需对接 |
| 对话自评估（维度④） | 后端后台给回答打分用于优化，不影响对话 | 无需对接 |
| 长期记忆（维度②E1） | 跨会话记住用户说过的事实（修了「旧事实被遗忘」缺陷） | 无需对接 |

## 7. 联调与验收建议

1. **基础连通**：用现有小程序 JWT 调 `GET /api/v1/persona/{device_id}/schema`，应返回 `fields` 元数据。
2. **设置生效**：PUT 设 `name=小福`，立即与设备对话，确认设备自称变为「小福」。
3. **回显**：GET 返回的 `custom.name == "小福"`，`persona.name == "小福"`。
4. **清除**：DELETE 后 GET，`custom` 为空、设备恢复默认人格。
5. **边界**：PUT 传 `{"name": null}` 应清除 name；传未知字段 `{"foo":1}` 应被忽略且 `400` 不报。
6. **归属**：用未绑定该设备的小程序账号调用，应稳定返回 `404`。

---

## 8. 变更与回滚

- 本 API 为**纯新增端点**，不改动任何既有接口 / WS 协议（符合「HTTP API 只扩不删改」红线）。
- 服务端回滚点：`prod-20260730-persona`（含人格 API）、`prod-20260730-rag`（含家庭 RAG）。如需回退，回滚镜像即可，不影响小程序客户端（旧版服务端无此端点时小程序应优雅处理 404/503）。
- 小程序侧建议：调用失败时**不阻断主流程**，设置页可离线缓存用户上次填写值，下次重试。
