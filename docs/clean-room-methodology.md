# 复果AI 脱 MIT 方法论（clean-room methodology）

> **本文性质**：fuguoai-server 摆脱 `xiaozhi-esp32-server`（MIT）派生的**方法论底稿**，不是代码说明，也不是 LICENSE。
> **配套证据（机读，已在仓内）**：主台账 `audit/EVIDENCE_LEDGER.md` · 行为门 `audit/*_gate.py` · clean-room 规格 `audit/cleanroom/*_spec.md` · 上游派生清单 `audit/THIRD_PARTY_LICENSES.md`。
> **公开版三件套**：本文 + 由台账抽取的 `docs/similarity-audit.md` + 由行为门汇总的 `docs/behavior-gate.md`。
>
> **为什么写这个方法论**：代码会过时，但"如何证明自己脱离了 MIT"这套判据与流程长期有效，可被任何重写 MIT 的项目复用。

---

## 0. 为什么需要方法论（而不是"git 改了就脱了"）

- **交叉互认门（行为门）≠ 脱 MIT**。行为门只证"没改坏"（OLD≡NEW 输出一致），不证"不是派生"。两件事必须分开。
- **git 改了、门过了，都不等于脱离 MIT 派生**。它们是必要条件，不是充分条件。
- 真正能证明脱 MIT 的是：**逐文件"派生 / 重写 / 契约锁定"的判据 + 可复核的证据链**。
- 判据来源分级（每条结论标注 `[硬·实测]` / `[硬·代码]` / `[推断(待验证)]` / `[未知]`），推断与未知不得当下单或开焊依据。

---

## 1. 两条铁律（踩坑后确立，必须遵守）

### 铁律一：相似度数字只能排序，不能定性
- `LOGIC`（measure_sim vs 上游 MIT）是把文件排队的工具，**不能据此判"抄 / 没抄"**。
- 反例：`LOGIC=1.000` 可能是 **0 行空文件 / 导出壳 / ABC（契约锁定 floor）**，**≠ 逐字抄**。
- 定性必须**回源**：读活文件（行数 + 形态）+ `git diff` + 实跑行为门。
- 任何结论标注来源级别；推断/未知条目不能拿去下单或开焊。

### 铁律二：改一处就要重算整条链
- 禁止"替换一个值就算修好"（典型：BUSY 19→22→4，每次只验证新脚有无冲突，没验证这个脚存不存在）。
- 改任何值都要**重新验证依赖它的所有结论**（像编译一样重跑全链），不能局部替换。

## 2. 判据分类法（逐文件归入一档）

口径来自 `audit/EVIDENCE_LEDGER.md`，六档：

| 档 | 含义 | 达标方式 |
|---|---|---|
| **C 重写达标** | clean-room 重写 + 行为门交叉互认 + `LOGIC<0.40` | 重写 + 门证 |
| **R 契约锁定豁免** | 公开名/库API/路径/第三方URL+字段/DTO 字段被调用方逐字锁定，`LOGIC<0.40` 数学不可达 | 重写 + 门证（不靠相似度压线） |
| **F 结构性地板** | 逻辑为 fuguoai 自有、由行为门认证等价（<40 行极小委派/骨架） | 豁免同契约锁定 |
| **X 真派生·待重写** | 相似度高且与上游逐行同逻辑，未给判据/未重写 | 必须重写 |
| **N 复果自有·待补原生判定** | 复果原生实现，与上游同功能巧合相似 | 补一条"原生判定"记录，不重写 |
| **O 待判定** | 有上游对应件且相似度高，未做"派生 vs 巧合相似"判定 | 补判定 |

> **当前覆盖率**：审计（`LOGIC≥0.40`）**58** 文件；已有判据（C/R/F）**58**；缺口（X/N/O）**0**。真派生(X)=0、原生待补(N)=0、待判定(O)=0。

## 3. clean-room 重写手法

- **按规格书独立编写**（`audit/cleanroom/*_spec.md`）：不读上游源码，只对齐公开契约（类名、被调用方法名、抽象方法签名）。
- **行为门（OLD≡NEW 交叉互认）**：新旧两版对同一输入跑同一输出，证"没改坏"。它是脱 MIT 的**"没改坏"证据**，不是"不是派生"证据——两条证据链分开建。
- **provenance tag（出身标记）**：每个文件打来源标记（自有 / 重写 / 契约锁定），形成可机读的出身链，供台账与审计消费。

---

## 4. 契约锁定策略（为什么 `LOGIC<0.40` 数学不可达）

- 公开契约（库 API、DTO 字段、第三方 URL+字段）被调用方**逐字锁定** → 相似度有结构性 floor，永远压不到 0.40 以下。
- 这类**不靠"压低相似度"达标**，而靠"证明这是被迫对齐的公开契约"豁免（R 档）。
- 这是判据里最容易被误判的一档：高相似度 ≠ 高派生风险，凡是公开契约对齐都天然高相似。

---

## 5. 公开这套方法论的意义

- **对自己**：审计底稿 / 法律证据 / 可复用资产。若有人质疑"是不是抄的"，直接甩 58 文件的审计记录 + 行为门；将来重写任何 MIT 项目，这套流程直接复用。
- **对社区**：GitHub 上大量 fork 小智的项目，绝大多数不知道"交叉互认门 ≠ 脱 MIT"、以为"git 改了 / 门过了"就脱了、不知道 `LOGIC 0.9+` 还是派生。本文 + 三件套正是这个空白的答案。
- **对项目本身**：公开细节是"防弹衣"——只公开代码不公开审计，别人可质问"你说重写怎么证明"；公开了 LOGIC 分 / 达标理由 / 行为门 / provenance tag，质疑者面对的是"这里有 58 个文件的审计记录，自己看"。
