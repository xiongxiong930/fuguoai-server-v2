# 复果AI 脱 MIT 方法论（clean-room methodology）

> **本文性质**：fuguoai-server-v2 摆脱 `xiaozhi-esp32-server`（MIT）派生的**方法论底稿**，不是代码说明，也不是 LICENSE。
> **配套证据（机读，已在仓内）**：主台账 `audit/EVIDENCE_LEDGER.md` · 行为门 `audit/*_gate.py` · clean-room 规格 `audit/cleanroom/*_spec.md` · 上游派生清单 `audit/THIRD_PARTY_LICENSES.md` · 上游对照快照 `audit/_reference_snapshot/`。
> **公开版三件套**：本文 + 由台账抽取的 `docs/similarity-audit.md` + 由行为门汇总的 `docs/behavior-gate.md`。
>
> **为什么写这个方法论**：代码会过时，但"如何证明自己脱离了 MIT"这套判据与流程长期有效，可被任何重写 MIT 的项目复用。本文是**可验证的脱 MIT 案例**，不是"一个重写的后端"。

---

## 0. 为什么需要方法论（而不是"git 改了就脱了"）

- **交叉互认门（行为门）≠ 脱 MIT**。行为门只证"没改坏"（OLD≡NEW 输出一致），不证"不是派生"。两件事必须分开建证据链。
- **git 改了、门过了，都不等于脱离 MIT 派生**。它们是必要条件，不是充分条件。
- 真正能证明脱 MIT 的是：**逐文件"派生 / 重写 / 契约锁定"的判据 + 可复核的证据链**。
- 判据来源分级（每条结论标注级别），推断与未知不得当下单或开焊依据：
  - `[硬·实测]`：在运行环境/真实数据上跑过验证。
  - `[硬·代码/台账]`：来自仓库内源码或审计台账（如 `EVIDENCE_LEDGER.md`）的直接事实。
  - `[推断(待验证)]`：有推理但未回源实证，需进一步确认。
  - `[未知]`：无依据，不得作为结论。

## 1. 两条铁律（踩坑后确立，必须遵守）

### 铁律一：相似度数字只能排序，不能定性
- `LOGIC`（measure_sim vs 上游 MIT）是把文件排队的工具，**不能据此判"抄 / 没抄"**。
- 反例：`LOGIC=1.000` 可能是 **0 行空文件 / 导出壳 / ABC（契约锁定 floor）**，**≠ 逐字抄**。
- 定性必须**回源**：读活文件（行数 + 形态）+ `git diff` + 实跑行为门。
- 任何结论标注来源级别；推断/未知条目不能拿去下单或开焊。

### 铁律二：改一处就要重算整条链
- 禁止"替换一个值就算修好"（典型：`BUSY 19→22→4`，每次只验证新脚有无冲突，没验证这个脚存不存在）。
- 改任何值都要**重新验证依赖它的所有结论**（像编译一样重跑全链），不能局部替换式"修复"。

## 3. 真实误判案例（方法论里最值钱的部分）

以下两轮误判是 campaign 的核心资产。**它们证明：不回源实证，相似度数字会反咬你一口。**

### 案例一：providers/tools/ 9 件 —— 从"🔴 真派生·逐字"纠正为"R 契约锁定豁免"
- **原误判**：9 个文件被判为 X「真派生·逐字抄」。
- **回源实测** `[硬·实测]`：全为 **R 契约锁定豁免**——
  - 1 件是 **0 行空文件**（`__init__.py`，1 字节），空-空比较 `LOGIC=1.000` 是数学必然，**不含任何代码**；
  - 6 件是 **纯导出壳**（`from .x import Y` + `__all__`，5–24 行），导出名被调用方锁定，无业务逻辑；
  - 2 件是 **枚举/数据类/ABC**，成员名/字段名被数十调用方逐字锁定。
- 工具链主体 15 个大文件工作树已重写，`LOGIC` 实测 **0.07–0.39**。
- **教训**：`LOGIC=1.000` ≠ 「逐字 MIT 代码」。空文件与导出壳必然 1.000，必须回源读文件再定性。

### 案例二：hass_* 4 件 —— 从"🟡 复果自有·巧合相似"纠正为"X 真派生→已重写"
- **原误判**：4 个 HomeAssistant 插件被判为 N「复果自有·与上游巧合相似」而**不重写**。
- **实测推翻** `[硬·实测]`：用 `contract_floor.py` 剥掉 LLM 工具 schema 后，`LOGIC-LOCK` 仍 **0.515 / 0.547 / 0.774 / 0.807**；且 fork-start 与 main **双基线数值完全相同**（说明 fork 时即上游原样），FULL 高达 0.85/0.79。
- **这不是巧合相似，是真派生**：已全部重写，重写后 `LOGIC` **0.494→0.126 / 0.605→0.438 / 0.853→0.471 / 0.820→0.583**，并以 `hass_plugins_gate.py` **61/61** 证明行为等价。
- **教训**：「这是我们自己的实现」这种**印象不是判据**——必须回源比对 + 剥契约后量化，才能区分巧合相似与复制。

> 这两轮的共通根因：**顺序反了**——先凭印象出方案，再被审查逼着查证，查证必然推翻前面的印象。正确顺序是**先建硬事实清单再排方案**，方案里每个值都要能在清单里查到出处。

## 4. clean-room 重写手法

- **按规格书独立编写**（`audit/cleanroom/*_spec.md`）：不读上游源码，只对齐公开契约（类名、被调用方法名、抽象方法签名）。spec 是重写契约，也是行为门的验收基准。
- **行为门（OLD≡NEW 交叉互认）**：新旧两版对同一输入跑同一输出，证"没改坏"。它是脱 MIT 的**"没改坏"证据**，不是"不是派生"证据——两条证据链分开建。
- **provenance tag（出身标记）规范**：每个文件在文件头/台账打来源标记，形成可机读的出身链，供台账与审计消费：
  - `OWN` 复果自有（fork 后新增，上游无对应）；
  - `REWRITE` clean-room 重写（有上游对应，已独立重写 + 门证）；
  - `LOCK` 契约锁定豁免（公开契约对齐，相似度 floor 数学不可达）；
  - `FLOOR` 结构性地板（<40 行极小委派/骨架，门证等价）。
  - 标记与 `EVIDENCE_LEDGER.md` 主表的「判据」列一一对应，禁止"标了 OWN 但台账是 REWRITE"的错位。

## 5. 契约锁定策略（为什么 `LOGIC<0.40` 数学不可达）

- 公开契约（库 API、DTO 字段、第三方 URL+字段、协议常量串）被调用方**逐字锁定** → 相似度有结构性 floor，永远压不到 0.40 以下。
- 这类**不靠"压低相似度"达标**，而靠"证明这是被迫对齐的公开契约"豁免（R 档）。
- 这是判据里最容易被误判的一档：高相似度 ≠ 高派生风险，凡是公开契约对齐都天然高相似。
- **量化手法（`contract_floor.py`）**：剥掉被锁定的契约部分（LLM schema、imports、协议串、枚举成员名）后重算 `LOGIC-LOCK`。实例：
  - `hass_play_music.py`：剥掉 schema+imports 后 NEW 仅剩 **194 个 token**（占全文 63%）为可自由改写部分，其余 36.6% 全为契约 → `LOGIC<0.40` 数学不可达，以门 61/61 证等价。
  - `hass_set_state.py` / `hass_get_state.py`：剥契约后 `LOGIC-LOCK` 分别 **0.297 / 0.364 < 0.40**。
  - `textUtils.py`：剥掉三张协议数据表（EMOJI_MAP / EMOJI_RANGES / 标点集）后 `LOGIC-LOCK` **0.283 < 0.40**。

## 6. 审计工具链（怎么度量、怎么复现）

| 工具 | 作用 | 局限 |
|---|---|---|
| `tools/scan_derivation.py` | 工作树 `.py` vs 上游 MIT 原仓同名文件，算 canonical FULL/LOGIC + git 改动状态 | 需上游对照；上游无同名 → 判复果自有 |
| `tools/similarity_report.py` | 整体重叠率 + 内容级归一化相似度（剥 `fuguoai_` 前缀后配对上游） | 仅度量，不定性 |
| `tools/contract_floor.py` | 剥掉锁定契约部分后重算 `LOGIC-LOCK`，证 floor 不可达 | 需人工指定锁定集 |

- **上游对照快照是硬依赖**：`scan_derivation*.py` 默认读 `_reference_snapshot/main/xiaozhi-server`；缺失时从本仓 fork 起点 git 历史重建（`8f051a8` 等）。**2026-11-01 状态：快照已恢复**（v2 仓自带 `_reference_snapshot/main/xiaozhi-server` @ bd981aa，OLD 仓父目录对应路径软链至此）⇒ `tools/scan_derivation_v2.py`（v2 权威版）与全部行为门均可在此仓独立实跑。本次已实跑复核：相似度扫描 122 同名文件全比对（exit 0）+ 122 文件逐一判据映射（X=0），59 门 aggregate `PASS=1249 FAIL=0` —— 该层结论现为 `[硬·实测]`，非台账背书。
- **度量口径**：canonical FULL/LOGIC（归一化空白/注释/命名前缀后比对）、AST 引用图（只关心引用结构，无效转义 SyntaxWarning 与相似度无关）。

## 7. 反模式 / 避坑清单

| 反模式 | 为什么错 | 正确做法 |
|---|---|---|
| "git 改了 = 脱 MIT" | 改了可能只是局部替换，行为仍派生 | 逐文件判据 + 证据链 |
| "行为门过了 = 脱 MIT" | 门只证"没改坏"，不证"独立" | 门证 + 相似度/重写判据分开 |
| "LOGIC 0.9+ 还当达标" | 高相似=派生风险高，除非契约锁定 | 回源看是否 R/LOCK floor |
| "用相似度压线代替定性" | 数字只能排序 | 回源读文件 + git diff + 实跑门 |
| "这是我们自己的实现"（凭印象） | 印象不是判据 | 剥契约后量化 + 双基线比对 |
| "替换一个值就算修好" | 不重算依赖它的结论 | 改一处重跑整条链 |

## 9. 公开这套方法论的意义

- **对自己**：审计底稿 / 法律证据 / 可复用资产。若有人质疑"是不是抄的"，直接甩 58 文件的审计记录 + 行为门；将来重写任何 MIT 项目，这套流程直接复用。
- **对社区**：GitHub 上大量 fork 小智的项目，绝大多数不知道"交叉互认门 ≠ 脱 MIT"、以为"git 改了 / 门过了"就脱了、不知道 `LOGIC 0.9+` 还是派生。本文 + 三件套正是这个空白的答案。
- **对项目本身**：公开细节是"防弹衣"——只公开代码不公开审计，别人可质问"你说重写怎么证明"；公开了 LOGIC 分 / 达标理由 / 行为门 / provenance tag，质疑者面对的是"这里有 58 个文件的审计记录，自己看"。
