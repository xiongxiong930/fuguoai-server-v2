# 复果AI v3.0 设备端线协议契约（固件实现规范）

> **受众**：实现 v3.0 固件的开发方。
> **交付方**：后端（`fuguoai-server`）。
> **来源级别**：本文每条标注 `[硬·代码]`（运行代码核实）/ `[硬·契约]`（已与固件核对的协议回复）/ `[需对齐]`（v3.0 分支仅部署在 canary、未在 git 仓，以实际握手为准）。
> **配套**：对讲细节见 `INTERCOM_DEVICE_INTEGRATION_CONTRACT.md`；tts/llm 消息形态见 `BACKEND_INTEGRATION_PROTOCOL.md`；本文件是 v3.0 的汇总与修正版，替代之前点对点回复的 `V3.0_PROTOCOL_REPLY.md`。

## 0. TL;DR — 五句话

1. 文本：**回复正文读 `tts.text`（逐句），`llm.text` 只是情绪 emoji，别拿它当正文。**
2. 音频：**WS 全程裸 opus，不加 4 字节 envelope**；上行 `[可选 8B ts][raw opus]`。
3. 版本协商：hello 带 `"version":"3.x"` 或 `capabilities` → 后端走 v3.0 分支；老固件走 legacy 分支，两套并存互不干扰。
4. 鉴权：Header `Bearer` 与握手后 JSON `auth` 消息**双认**，固件发哪种都行。
5. 业务（日程/提醒/留言/对讲）全部走 `{"type":"iot",...}` 通道。

**两项必须先在固件侧落（详见 §5）**：① 去掉 4 字节 envelope；② 改读 `tts.text` 渲染正文。

## 1. 版本协商（握手）

- 设备 hello 带 `"version":"3.x"` 或上报 `capabilities` → 后端置 `protocol_version="3.0.0"`，走 v3.0 welcome（回显 capabilities、ts 头开启）。
- 老固件（无 version / 无 capabilities）→ `protocol_version="1.0"`，走 legacy welcome（回显 `audio_params`、ts 头默认关）。两种 welcome 后端都实现，按版本分叉，**互不影响**。
  - legacy 分支实现位置：`fuguoai_core/handle/helloHandle.py`（`_merge_aec_ready_into_welcome`）。[硬·代码]
  - v3.0 分支（`_build_v30_welcome`）**当前仅部署在 canary，未在 git 仓**；实现时以 canary 实际握手为准，必要时后端补发权威 welcome 样例。[需对齐]
- 鉴权双认：`Authorization: Bearer <token>`（Header）**与** 握手后的 JSON `{"type":"auth",...}` 消息，后端都放行。固件无需二选一。[硬·契约 V3.0_PROTOCOL_REPLY ③]

## 2. 文本下行（★ 固件必须修正）

- **回复正文（整句字幕）在 `tts` 消息的 `text` 字段**（`sentence_start` / `sentence_end` 流）。[硬·代码 `fuguoai_core/handle/sendAudioHandle.py:62` `_build_tts_message`]
- `llm` 消息的 `text` **仅作情绪 emoji 指示**（如 🙂），**不是回复正文**。[硬·代码 `fuguoai_core/utils/textUtils.py:112`]
- **v3.0 固件必须读 `tts.text` 渲染正文**。若只读 `llm.text` 会只看到 emoji 而缺字——这是此前文本显示异常的真正根因，非后端缺发。
- 后端**不下发第二套文本**（曾评估在末尾补 final 帧的方案已弃用，保持单通道清爽）。

---

## 3. 二进制音频（WS 裸 opus）

- WS 音频全程**裸 opus**（16k / 单声道 / 20ms / 无任何头字节）。[硬·契约 `INTERCOM_DEVICE_INTEGRATION_CONTRACT.md:14` + `_decode_opus_packet` 直接 `decode(raw_bytes)`，不剥头]
- 上行：`[可选 8B ts][raw opus]`。**不要加 4 字节 envelope**——v3.0 文档曾误把 legacy/串口帧的 `BinaryAudioFrame` 套到 WS 上，已纠正。[★ 固件修正项]
- 下行：裸 opus，无 ts 前缀、无 envelope。
- ts 头（8B）：单位 µs、小端、整帧最前（ts 之后直接 raw opus）；**后端 AEC 对齐用服务端时钟**，`connection.py:643` `local_ts=int(time.time()*1000)`，ts 头仅信息性、不驱动 AEC。

## 4. 业务通道（iot）

全部业务控制走 `{"type":"iot",...}`：[硬·代码 `iot_executor` / `devices_routes` / `networked_reminder_scheduler` / `intercom_call_store` / `voicemail_player`]

- **日程**：下行 `schedule_push`（`tasks` / `deletes`），构造见 `fuguoai_core/utils/schedule_downlink.py`。
- **网络提醒**：`reminder.fired` 经事件 WS 推送 + 设备语音播报（`networked_reminder_scheduler.py:432`）。
- **语音信箱**：设备上线且空闲自动播报；按设备 `iot_descriptors` 能力分流新 `PlayMessage` 通道 / 旧 `vm-server/SetIntercom` 虚拟对端通道（`voicemail_player.py`）。
- **对讲**：`DeviceControl.SetIntercom{peer, action}`，控制面/数据面共用同一条 WS，详见 `INTERCOM_DEVICE_INTEGRATION_CONTRACT.md`。

## 5. WS 端点

- 设备 / 手机对讲：`ws://<host>:8000/fuguoai/v1/`（手机侧 `role=phone`，身份由 JWT 派生 `phone-<uid>`）。[硬·代码 `fuguoai_core/websocket_server.py` / `http_server.py:502`]
